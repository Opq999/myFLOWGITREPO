## What this is, in plain English
This workflow introduces the Model Context Protocol (MCP), an open standard designed to make AI plugins portable. Historically, building extensions for AI models like ChatGPT meant creating a unique version for each platform. MCP changes this by providing a common way for plugins to communicate with various AI clients, including ChatGPT and other AI assistants.

This approach is advanced because it requires coding skills, setting up a development environment, and understanding server deployment. It's not a simple copy-paste recipe, as the exact instructions for running and deploying the plugin live within code notebooks, official documentation, and evolving tools.

The core idea is to write your plugin's logic once, and the MCP handles the complex task of connecting your tool to different AI models. This means your plugin can work across multiple AI platforms without needing to be rewritten for each one, saving developers time and effort.

## What you can use it for
*   **Build a universal AI tool**: Create a single backend for your service that can be used by ChatGPT, other AI assistants, and even integrated development environments (IDEs).
*   **Automate tasks across platforms**: Develop a plugin that performs a specific action (like looking up information or managing data) and make it accessible from any MCP-compliant AI.
*   **Extend AI capabilities**: Give AI models access to real-time data or specialized functions that are not built into the model itself.
*   **Create portable data lookups**: Develop a tool, like the HTTP status lookup example, that provides instant, structured information to an AI model.

1.  **Prepare your environment**: Ensure you have Node.js version 18 or higher installed. 2.  **Initialize your project**: Open your terminal or command prompt and create a new directory for your plugin, then navigate into it. Initialize a new Node.js project and install the necessary libraries:

    ```bash

    mkdir http-status-plugin
    cd http-status-plugin
    npm init -y
    npm pkg set type = module

    ```

    ```powershell

    ```

    You should see a new `package.json` file and a `node_modules` folder created in your project directory.

3.  **Implement the server logic**: The core of your plugin is a Node.js server that uses the `@modelcontextprotocol/sdk`. The excerpt provides a function `buildServer` that defines a tool called `lookup_http_status`. This tool takes an HTTP status `code` as input and returns its `phrase` and `meaning`.

    ```javascript
    import { createServer } from "node:http";
    import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
    import { StreamableHTTPServerTransport } from "@modelcontextprotocol/sdk/server/streamableHttp.js";
    import { z } from "zod";

    const STATUS = {
      200: ["OK", "The request succeeded."],
      404: ["Not Found", "The server found nothing at this URL."],
      429: ["Too Many Requests", "Rate limit exceeded."]
    };

    function buildServer() {
      const server = new McpServer({
        name: "http-status",
        version: "1.0.0"
      });
      server.registerTool(
        "lookup_http_status",
        {
          title: "Look up an HTTP status code",
          description: "Provides details for specific HTTP codes.",
          inputSchema: {
            code: z.number().int().min(100).max(599)
          },
          outputSchema: {
            code: z.number(),
            phrase: z.string(),
            meaning: z.string()
          },
          annotations: {
            readOnlyHint: true,
            destructiveHint: false,
            openWorldHint: false
          }
        },
        async ({ code }) => {
          const [phrase, meaning] = STATUS[code] ?? ["Unknown", "Entry missing."];
          return {
            content: [
              {
                type: "text",
                text: `${code} ${phrase}: ${meaning}`
              }
            ],
            structuredContent: {
              code,
              phrase,
              meaning
            }
          };
        }
      );
      return server;
    }
    ```

    This code defines the logic for your plugin's tool. The excerpt mentions using `createServer` from `node:http` and `StreamableHTTPServerTransport` to run this server, but the full implementation for connecting these pieces and making the server runnable and accessible is not provided in the source. You would typically need to create an HTTP server instance, pass the `McpServer` to the `StreamableHTTPServerTransport`, and then listen on a specific port.

4.  **Next steps (not covered in excerpt)**: To make this plugin functional with ChatGPT, you would need to:

## Notes & variations
*   **Do you even need this?**: For simpler tasks, you might not need a full plugin. ChatGPT's custom instructions or direct API calls (if you're comfortable with coding) can sometimes achieve similar results without the overhead of building and deploying a full MCP server. Consider if a simpler approach meets your needs before diving into plugin development.
*   **Free-tier limits**: While the development tools (Node.js, npm, SDKs) are free, deploying and publishing a plugin via the OpenAI Platform typically requires a paid developer account and incurs usage costs based on how often your plugin is used.
*   **Common pitfall**: Ensuring your server is truly stateless is crucial for reliability and scalability. The OpenAI plugin infrastructure expects that every request is handled independently, without relying on information from previous chat sessions. Avoid storing session-specific data directly on the server to prevent unexpected behavior.
