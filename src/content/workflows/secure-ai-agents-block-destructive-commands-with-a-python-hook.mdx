## What you'll get
You'll create a script that acts as a 'seatbelt' for your AI agent, preventing it from running dangerous commands like deleting files or forcing code pushes. This approach works by checking commands before they are executed, ensuring they don't contain harmful patterns or target sensitive areas.

## Tools you need
*   **Python** (free): A programming language used here to parse commands and check their safety.
*   **Bash** (free): A command-line shell used to run scripts and execute commands on your system.

## Steps
1.  **Create the initial blocklist script**: This script checks for specific destructive commands. Save this code in a file named `guard-bash.sh`.

    ```bash
    #!/bin/sh
    # PreToolUse hook: reads { tool_name, tool_input } JSON on stdin.
    # exit 0 = allow | exit 2 = block, stderr goes back to the agent.
    cmd=$( python3 -c 'import json,sys; print(json.load(sys.stdin)("tool_input").get("command",""))' 2 /dev/null )
    case " $cmd " in 
        * "rm -rf $ " * | * "rm -rf ~" * | * "rm -rf /" * | \ 
        * "git push --force" * | * "git push -f" * | \ 
        * "DROP TABLE" * | * "chmod -R 777 /" * )
        echo "SEATBELT: blocked — destructive pattern matched in: $cmd " 2
        exit 2
        ;; 
        * )
        exit 0
        ;; 
    esac
    ```

    After saving, make the script executable by running `chmod +x guard-bash.sh` in your terminal. This script should allow safe commands and block dangerous ones.

2.  **Test the initial script**: You can test this script by feeding it example commands. For instance, to test blocking `rm -rf /`, you would run:

    ```bash
    echo '{"tool_input":{"command":"rm -rf /"}}' | ./guard-bash.sh
    ```

    You should see an error message indicating the command was blocked, and the script should exit with a non-zero status (indicating a block).

    ```bash
    export PROJECT_ROOT="/path/to/your/project"
    ```

    Replace `/path/to/your/project` with the actual path to your project folder.

5.  **Run your AI agent with the Python hook**: When your AI agent is configured to use a 'PreToolUse' hook, point it to this Python script. ## Notes & variations
*   **Common mistake**: The initial script (`guard-bash.sh`) can be easily bypassed because it relies on simple string matching. For example, commands like `echo cm0gLXJmIC9EYXRhL3NlY3JldA== | base64 -d | sh` hide the destructive command within other operations. The improved Python script using `shlex` is more resilient.
*   **Tip for better results**: The `targets_of` function in the Python script is crucial. A robust implementation would carefully parse the command arguments to identify all file paths being targeted and then check if they fall within the allowed `PROJECT_ROOT`. This requires more sophisticated parsing logic.
*   **Alternative**: For simpler needs, you might consider using a more opinionated AI agent framework that has built-in safety features, though custom hooks offer more control.
