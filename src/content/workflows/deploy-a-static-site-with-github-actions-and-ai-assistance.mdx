## What you'll get
You will learn how to set up an automated workflow using GitHub Actions to deploy your static website. This approach builds your site on GitHub's servers, saving you the manual step of building and pushing files locally. It's useful for anyone who wants to streamline their website deployment process.

## Tools you need
*   **GitHub Actions** (freemium): A tool integrated into GitHub to automate software development tasks, like building and deploying websites.
*   **Hugo** (free): A fast website building tool that turns your content into a static website.
*   **Git** (free): A system for tracking changes in your code and collaborating with others.
*   **AI Agent** (freemium): A tool like ChatGPT, Claude, or Gemini that can help you understand and generate code or configuration files.

## Steps
1.  **Understand the deployment difference**: Chat with an AI agent to grasp the core difference between building locally and pushing files versus using GitHub Actions to build on GitHub's servers. The AI should explain that GitHub Actions automates the build process on their platform.
    *   **What to expect**: A clear explanation of the two methods.
2.  **Decide on repository structure and theme tracking**: Ask the AI agent to explain the trade-offs for where your Hugo source code should live (same repository on a new branch, or a separate repository) and how to track your theme (as a Git submodule or vendored). Then, make your choice based on the AI's explanation.
    *   **What to expect**: You will choose between options like "same repository and new branch" and "Git submodule".
3.  **Prompt the AI agent to set up your project**: Use a prompt similar to the one below, replacing bracketed information with your specific details. The AI will help you add the necessary files and configurations.

    ```
    In this folder, Mysite is the original folder used to generate the static website using Hugo, and then it was connected to GitHub to deploy GitHub Pages. I used hugo to generate the files and push the public folder to GitHub. Now I want to:
    1. Switch the theme. The new theme has been configured in the Mysite_paper folder, so please use this folder.
    2. Switch from pushing the public folder to using GitHub Actions. Don't do it now. First tell me your plan.
    ```

    *   **What to expect**: The AI agent will outline a plan and then help implement it by adding a Git submodule, a .gitignore file, and the workflow file to your local project.
4.  **Implement the Git submodule**: If the AI didn't fully automate this, manually add your chosen theme as a Git submodule. This links your project to the theme's repository, allowing for easier updates.
    *   **What to expect**: A new entry in your project's `.gitmodules` file and a `.gitmodules` file itself, along with the theme's files being managed by Git.
5.  **Create a `.gitignore` file**: Ensure a `.gitignore` file is present in your project. This file tells Git which files or folders to ignore, such as the `public` folder that will be generated by Hugo during the build process.
    *   **What to expect**: A `.gitignore` file containing entries like `/public/`.
6.  **Create the GitHub Actions workflow file**: The AI should help create a file named something like `main.yml` (or similar) inside a `.github/workflows/` directory in your project. This file contains the instructions for GitHub Actions.
    *   **What to expect**: A YAML file with steps to check out your code, set up Hugo, build the site, and deploy it.
7.  **Push your changes to GitHub**: After the AI has made the local changes, commit and push them to your GitHub repository.
    *   **What to expect**: Your local changes, including the new theme configuration and the workflow file, are uploaded to GitHub.
8.  **Monitor the GitHub Actions run**: Go to your GitHub repository, navigate to the 'Actions' tab, and watch the workflow run. It should build your Hugo site and deploy it.
    *   **What to expect**: A successful workflow run, indicated by a green checkmark, and your website updated on GitHub Pages.

## Notes & variations
*   **Free tier alternative**: GitHub Actions provides a generous amount of free build minutes for public repositories, which should be sufficient for most personal projects and small businesses.
*   **Common mistake**: Forgetting to add the `public` folder to your `.gitignore` file can cause issues, as Git might try to track the generated site files instead of ignoring them.
*   **Tip for better results**: Clearly define your project structure and theme management preferences to the AI agent upfront. This helps the AI generate a more accurate and tailored setup for your specific needs.
