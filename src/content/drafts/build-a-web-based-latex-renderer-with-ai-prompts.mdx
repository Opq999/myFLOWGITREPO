## What this is, in plain English
This entry describes how an advanced AI, specifically a code-generating model like Claude Code, can be used to build a custom web application. Instead of using an existing tool, you ask the AI to create one for you based on your detailed instructions. This is an advanced concept because it involves generating code and then deploying that code to make a working website, which requires technical skills.

The specific goal here is to create a web-based LaTeX renderer. LaTeX is a document preparation system often used for scientific papers and complex math. The idea is to build a tool where you can share a link, and the LaTeX code embedded in the link's address (after the `#` symbol, called a fragment hash) is automatically displayed as a rendered document.

There is no simple copy-paste recipe for this workflow because the exact instructions live within the AI's code generation process, and the resulting web application code would need to be set up and hosted on a web server. The author provides the prompt used to ask the AI to build this tool, but not the generated code or the steps to deploy it.

## How it actually works
To build a web-based LaTeX renderer using AI, you would provide a detailed prompt to a code-generating AI like Claude Code. The AI would then generate the necessary web code (HTML, CSS, and JavaScript) to create the application. The author's prompt described the desired features, such as rendering LaTeX from a URL fragment, supporting compression, and including an editor view.

Once the AI generates the code, you would need to set up a web development environment and deploy the code to a web server or hosting service for it to become a live, usable web application. The author doesn't share the exact generated code or the specific deployment steps, as these would depend on the AI's output and your chosen hosting method. The prompt used by the author was:

```
I want a tool where you can link to it with a fragment hash #code-here and it treats that code as LaTeX and renders it really effectively. It should also support a prefix which means the latex is compressed with a custom compression dictionary optimized for latex. Use the best available latex render library from a CDN (consider WebAssembly too). If loaded without a fragment hash show an editor you can paste latex into and then toggle to a "rendered" view. That rendered view should be bookmarkable. The #fragment view should let you switch to edit source too.
```

## Words you'll see, explained
*   **LaTeX**: A document preparation system widely used for scientific papers, technical documents, and complex mathematical formulas.
*   **Fragment hash (#)**: The part of a web address (URL) that comes after a hash symbol, often used to link to a specific section within a web page or, in this case, to pass data to the web application.
*   **CDN (Content Delivery Network)**: A network of servers distributed globally that delivers web content, such as libraries and assets, quickly to users based on their geographical location.
*   **WebAssembly**: A technology that allows code written in languages like C++ or Rust to run very fast directly within web browsers, improving performance for complex web applications.
*   **Repo (Repository)**: A storage location for code, typically managed with version control systems like Git, where developers can track changes and collaborate.
*   **iframe sandbox**: A security feature in web browsers that allows embedding content from other sources (like another web page) within a restricted environment, limiting what the embedded content can do.
